## Register journey files

Add Arazzo 1.1 JSON files to the workbench configuration. In Laravel's `config/sendproof.php`, set:

```php
'journeys' => [base_path('journeys/store.arazzo.json')],
```

In Symfony's `config/packages/sendproof.yaml`, set:

```yaml
sendproof:
  journeys:
    - '%kernel.project_dir%/journeys/store.arazzo.json'
```

Use unique filenames ending in `.arazzo.json` and application-relative OpenAPI URLs such as `/openapi/v1.json` in `sourceDescriptions`. Place `store.expect.json` alongside `store.arazzo.json` to attach expectations. Sendproof supplies empty expectations when there is no sibling. The workbench advertises and serves both files under its normal authorization policy, including any application path base in their URLs.

## Preview sessions

The Laravel/Eloquent and Symfony/Doctrine adapters advertise `previewSessions: false`. PHP-FPM and the PHP development server release the PHP transaction objects at request shutdown. Multi-request sessions have no enable switch. A future implementation could retain those transactions in long-lived Octane or FrankenPHP workers. See [store limits](data-stores.md#preview-session-limits).

## Develop

Requires PHP 8.2+, Composer and `ext-pdo_sqlite`. Dependencies install into each package's own `vendor/`. The MongoDB hook needs `ext-mongodb` (and phpredis needs `ext-redis`); the tests for a store skip when its client or service is missing.

```sh
sh adapters/php/scripts/prepare.sh   # packs the shared UI, runs composer install
sh adapters/php/scripts/test.sh      # PHPUnit for core, laravel and symfony
node tests/conformance/run.mjs php-laravel
node tests/conformance/run.mjs php-symfony
```

The data-store checks need the compose services: `docker compose -f tests/conformance/compose.yml up -d --wait mongodb redis dynamodb`.

## Release packaging

The workbench UI in `core/resources/ui` is generated by `tools/pack-ui.mjs` and is **not tracked in git**, so a bare git tag would install without it. Packagist reads `composer.json` from a repository root, so each package is released to its own split (mirror) repository, and the mirror tree must contain the UI. Build those trees with the shared release driver:

```sh
node tools/pack-all.mjs --only packagist --verify   # writes artifacts/packages/packagist/sendproof-{core,laravel,symfony}-<version>.zip
```

Each ZIP holds exactly the tree to commit to a mirror repository root: `composer.json` (siblings pinned to the release, repository and issue links stamped from `adapters/go/MODULE_PATH`, no path repositories or dev tooling), `LICENSE`, `README.md`, `src/` and, for core, `resources/ui`. The module (`tools/release/packagist.mjs`) validates each manifest with `composer validate --strict`, fails if a ZIP contains `vendor/` or `tests/`, and `--verify` installs the ZIPs through a Composer [`artifact` repository](https://getcomposer.org/doc/05-repositories.md#artifact) into a fresh Laravel app and serves `/sendproof/`. The ZIPs carry no `version`: Packagist takes versions from git tags.
